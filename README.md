# Venxe

An interactive 3D developer portfolio prototype built with Three.js, featuring a laptop and coffee. The site is fully static and can be hosted on GitHub Pages.

Start the local development server with Node.js **22.15 or later**:

```sh
npm run dev
```

Preview the site at http://127.0.0.1:4173. No package installation or build step is required.

The laptop display uses a 1200 × 675 desktop texture and a 3.46 × 1.94625 model-unit panel, both exactly 16:9. The chassis and lid share a 3.6 × 2.06625 footprint, with the keyboard and touchpad compressed in depth to fit. Physical ports and camera details retain their dimensions. Desktop and model dimensions are defined in `src/config.js`.

Zoom in to closely frame the whole laptop from a low front angle, with its keyboard visible and equal margins around its visible outline. A new inward zoom gesture centers the entire desktop, preserving its proportions with dark margins on different screen shapes. The left shell bar, bottom edge, and both sides remain visible, including on tall phone screens. Only the desktop and plain background appear in this view; site controls are hidden. Each outward gesture, minus-key press, or Escape press returns one stage: desktop to laptop, then laptop to the saved scene view. Wheel events separated by less than 200 ms belong to one gesture; lift all fingers after a pinch or release a zoom key before changing another stage. Clicking the screen or pressing Enter or Space opens the laptop view.

The laptop runs a local visual simulation of **Hyprland + Caelestia Shell**. Its persistent left bar has five workspaces, the launcher, local clock, network, battery and session controls. Select the clock for the four-tab Dashboard (calendar, media, performance and weather). The top-right bell opens notification history; bottom-right sliders open Utilities. Network and battery also have bar popouts. Volume, mute, brightness, Wi-Fi, DND and power mode affect only the simulated laptop. CPU and memory meters sum the system baseline and per-window application profiles. A new session starts around 44% CPU and settles toward a 4% idle baseline; each app adds persistent idle CPU/RAM costs and a short launch CPU burst. Terminal uses 0.6 CPU percentage points and 0.08 GiB RAM per window; Wallpapers uses 1 point and 0.16 GiB. All workspaces contribute, refocusing an existing window does not duplicate its load, and closing it releases its resources smoothly. Startup and launch bursts age in real time even when the meters are hidden. Small fluctuations add visual variation; power saver reduces CPU load. Application profiles live alongside app definitions in `src/desktop-theme.js`. Dashboard and session-lock meters share these values, updating at most 20 times per second while visible. Hidden panels and reduced motion pause the animation. Weather, storage and battery are fixed demo data; the media card is a visual preview without audio playback.

Open Launcher with the logo or Alt+D. Search or select Terminal and Wallpapers to open local demo windows; two windows tile side by side. Alt+1 through Alt+5 changes workspaces; Alt+Shift+1 through Alt+Shift+5 moves the active window. Window controls close or toggle fullscreen. The wallpaper picker uses bundled images and updates the desktop, greeter and lock screen together. There is no command execution or access to your files.

The page starts signed in. Caelestia session options offer Lock, Log Out, Restart and Power Off. Locking or closing the lid preserves windows and workspaces in the Caelestia session lock. Logging out clears the session and opens **SDDM Locklike**: a large welcome followed by a three-column sign-in card, system-information panel, narrow clock, shaped avatar, masked password and power buttons. The first key or tap reveals the card without entering a password character; Tab keeps native navigation. Escape closes a drawer, then returns a revealed SDDM card to its welcome, before stepping back the camera. Reduced motion skips reveal, shape and error animations. Native password/search inputs support keyboard typing, paste and mobile keyboards.

Click the physical Power key at the right of the keyboard function row to start when off. Hold it for two seconds to force power off while running or booting. Keyboard users can tab to Laptop power and hold Enter or Space. Cancelling, dragging away, adding a second pointer or leaving the tab cancels the hold. Shutdown from the desktop view returns to the laptop so the key is reachable.

Cold boot simulates CachyOS on x86-64 UEFI with quiet splash: a brief black firmware interval, a Limine 12.9.3 menu, one short kernel/initramfs loading screen, the Plymouth waiting indicator, the CachyOS logo animation, a static white logo, a black handoff, then the SDDM Locklike welcome. Verbose hardware and systemd logs are suppressed. The original [CachyOS Plymouth theme](https://github.com/CachyOS/plymouth-theme/tree/29a5d7648fbe32ee4ea241919f14363be0a98903/cachyos-bootanimation) supplies 41 waiting frames and 88 logo frames, played at 30 FPS on black. These PNGs are bundled locally with source and license attribution in `assets/boot/cachyos/README.md`. Boot artwork loads only when starting the simulated computer; delayed or failed frames fall back to the final logo or CachyOS text and never delay login. This reproduces the animated theme, rather than every hardware-dependent CachyOS configuration. The profile models an unencrypted Btrfs root subvolume on NVMe and an SDDM login manager. The selected Hyprland session starts only after successful password verification; the session uses the Caelestia shell and Locklike greeter. No operating system or bootloader binaries are executed.

The simulation uses 450 ms firmware, a 3000 ms selection countdown, 450 ms loading, 2000 ms waiting, 2934 ms logo animation, 300 ms final logo and 150 ms handoff. An untouched cold boot takes 9.284 seconds; restart takes 11.284 seconds including shutdown and its black interval. These timings describe the portfolio simulation, not measured CachyOS startup performance.

In laptop or desktop views, Limine shows an expanded CachyOS tree with linux-cachyos, linux-cachyos-lts and a collapsed Snapshots folder, over a dark navy background with soft violet highlights. Use Up/Down to cycle through rows, Home/End to select the first/last row, and Enter, Space or Right to boot a kernel or toggle a folder. Left collapses CachyOS. Snapshots expands to show that no snapshots are installed. The E Edit and B Blank Entry legends match the reference; configuration editing remains unavailable. Hover selects a row; click or tap activates it. Scrolling over a row selects without zooming. Any key or mouse interaction on the screen cancels the three-second autoboot countdown, leaving the menu waiting for confirmation. Escape still returns one view and Tab still moves native keyboard focus. Dragged, cancelled or multiple-touch taps cannot start an entry. The LTS entry loads its own vmlinuz-linux-cachyos-lts kernel and initramfs-linux-cachyos-lts.img, then follows the same quiet splash to login. Each new boot restores the normal selection. Closing the lid allows boot to continue; returning from a background tab catches up elapsed stages and animation frames, while an interrupted menu stays waiting. Reduced motion shows only the final static logo, caps each finite non-menu stage at 400 ms and preserves the three-second selection countdown, for a 5.05-second cold boot. Boot screens repaint when their stage, selection, countdown, visible loader lines or animation frame change.

The password is never displayed or stored as plaintext in the source. Verification uses a local SHA-256 digest via Web Crypto (HTTPS or localhost); this is a desktop simulation, not an access-control boundary. Enter submits the native masked password field. No password or session is saved in browser storage. Volume, brightness, wallpaper, network and power-mode preferences survive simulated restarts within the page. `src/system.js` owns timed power/session transitions through `send(event, value)`, `update(time, reducedMotion)`, the read-only `state`, and `dispose()`. During `phase: 'booting'`, `state.boot` exposes the stage, selected entry, countdown seconds (`null` when inactive), immutable visible loader lines and `frameIndex` (`null` outside Plymouth); otherwise it is `null`. `boot-select` accepts `normal` or `lts`, `boot-confirm` starts the selection and `boot-interrupt` cancels autoboot. These events apply only to the Limine menu with the lid open. Labels, paths, the documented quiet-splash profile, durations and animation dimensions live in `src/boot-profile.js`, based on the [Limine 12.9.3 configuration and source](https://github.com/Limine-Bootloader/Limine/tree/v12.9.3) and [CachyOS boot documentation](https://wiki.cachyos.org/configuration/boot_manager_configuration/). Model brightness combines the user brightness setting, system state and lid brightness.

The slim laptop has a perforated cooling grille, side vents, two USB-A sockets, USB-C, an Ethernet socket with a folding lower jaw, and a barrel power socket. All ports start empty. Click or tap the camera cover above the display to slide it open or closed. Keyboard users can tab to the Camera privacy cover button; it becomes visible when focused. The camera indicator stays off, and the scene does not request camera access.

`createLaptop()` exposes `ports` records with `id`, `type`, `group`, and `anchor`. Attach future connector models to the appropriate anchor, whose local +Z points out of the socket. The Ethernet group's `ethernet-jaw` pivots around local X; rotating it to 0.5 radians opens the mouth. `webcam.setClosed(boolean)` and `webcam.update(deltaSeconds, reducedMotion)` control the cover.

Click or tap the front-center lifting notch to close or open the laptop lid, or tab to the Laptop lid button. Closing the lid leaves screen focus; screen and camera-cover controls become available again once the lid is fully open. `lid.setClosed(boolean)` and `lid.update(deltaSeconds, reducedMotion)` control the hinge, with `closed` reporting the target state and `moving` reporting an unfinished transition. Reduced motion changes the lid state immediately.

At a lid opening of 20 degrees or less, the display and its glow fade out over 100 ms. At 30 degrees or more, the display waits 150 ms, then fades in over 600 ms, continuing after the hinge settles. Reduced motion bypasses these delays and fades. `lid.update()` continues updating the display while returning whether the hinge geometry changed.

Run `npm run check` to verify imports, geometry budgets, chassis/port clearance, attachment orientation, camera cover behavior, desktop controls, power/session transitions and scene interactions. Credential tests use a crypto-boundary fixture rather than the real password. These checks do not measure GPU pixels, native browser behavior, screen-reader output or FPS.

`src/screen.js` coordinates the single CanvasTexture, native controls and UV input. `src/desktop-shell.js` owns local shell/workspace state, `src/desktop-layout.js` supplies shared drawing/hit geometry, and `src/desktop-theme.js` defines design tokens. `src/screen-painter.js`, `src/login-painter.js` and `src/boot-painter.js` paint their respective surfaces. Source revisions, bundled fonts and artwork licenses are listed in `assets/desktop/README.md`. `src/power-input.js` handles physical and accessible power-button gestures, while `src/system.js` owns power/session transitions. Interaction checks share `scripts/test-interactions.mjs` and run view, keyboard, hardware and desktop scenarios sequentially through `scripts/check-interactions.mjs`.
