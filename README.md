# Venxe

An interactive 3D developer portfolio prototype built with Three.js, featuring a laptop and coffee. The site is fully static and can be hosted on GitHub Pages.

Start the local development server with Node.js **22.15 or later**:

```sh
npm run dev
```

Preview the site at http://127.0.0.1:4173. No package installation or build step is required.

The laptop display uses a 1200 × 675 desktop texture and a 3.46 × 1.94625 model-unit panel, both exactly 16:9. The chassis and lid share a 3.6 × 2.06625 footprint, with the keyboard and touchpad compressed in depth to fit. Physical ports and camera details retain their dimensions. Desktop and model dimensions are defined in `src/config.js`.

Zoom in to closely frame the whole laptop from a low front angle, with its keyboard visible and equal margins around its visible outline. A new inward zoom gesture centers the entire desktop, preserving its proportions with dark margins on different screen shapes. The taskbar, bottom edge, and both sides remain visible, including on tall phone screens. Only the desktop and plain background appear in this view; site controls are hidden. Each outward gesture, minus-key press, or Escape press returns one stage: desktop to laptop, then laptop to the saved scene view. Wheel events separated by less than 200 ms belong to one gesture; lift all fingers after a pinch or release a zoom key before changing another stage. Clicking the screen or pressing Enter or Space opens the laptop view.

The GNOME-inspired top bar shows your local date and time. Its desktop layout stays fixed at 36 pixels high, with 14-pixel text and 16-pixel icons, independently of camera zoom or viewport size. In laptop and desktop views, select the clock to browse the calendar, or the Wi-Fi, sound and battery indicators to open quick settings. Panels also keep fixed desktop dimensions: 360 pixels wide, with a height of 384 for the calendar, 236 for quick settings, or 324 with the Wi-Fi list expanded. Volume, mute, network selection and power mode control the simulated laptop; they do not change your device settings. Tab to the native desktop controls to use the keyboard, and use arrow keys to select dates or adjust volume. Escape closes an open panel before stepping back a view. Reloading resets the simulated settings.

The power button in quick settings opens Log Out, Restart and Power Off. The page starts signed in. Logging out or reopening the lid shows a clock screen; shutdown fades to black, and restart includes a black interval and the Linux boot sequence before sign-in. Press any key, click or tap the clock screen to slide the date and time upwards and reveal the avatar, CachyOS · Hyprland session label and password field. The first key only opens and focuses the form; subsequent keys enter the password. Reduced motion skips the reveal animation. Click the physical Power key at the right end of the keyboard's function row to start a powered-off laptop. Hold it for two seconds to force power off while running or booting. Keyboard users can tab to Laptop power and hold Enter or Space. Cancelling, dragging away, adding a second pointer or leaving the tab cancels the hold. Shutdown from the desktop view returns to the laptop so the key is reachable.

Cold boot simulates CachyOS on x86-64 UEFI: a brief black firmware interval, a Limine 12.9.3 menu, kernel/initramfs loading, Linux hardware messages, systemd initramfs and root-filesystem handoff, system services, then the existing clock screen. An untouched cold boot takes 8 seconds; restart takes about 10 seconds including shutdown and its black interval. The static boot profile uses an NVMe disk, a Btrfs root subvolume and an SDDM login manager. The selected Hyprland session starts only after successful password verification; the desktop and login design remain the existing portfolio interface. No operating system or bootloader binaries are executed.

In laptop or desktop views, Limine offers normal and fallback initramfs entries. Use Up/Down to cycle, Home/End to select the first/last entry, and Enter, Space or Right to boot. Hover selects an entry; click or tap boots it. Scrolling over a row selects without zooming. Any key or mouse interaction on the screen cancels the three-second autoboot countdown, leaving the menu waiting for confirmation. Escape still returns one view and Tab still moves native keyboard focus. Dragged, cancelled or multiple-touch taps cannot start an entry. Fallback loads the same kernel with a broader-driver initramfs, then reaches the same login screen. Each new boot restores the normal selection. Closing the lid allows boot to continue; returning from a background tab catches up elapsed stages, while an interrupted menu stays waiting. Reduced motion caps each finite non-menu stage at 400 ms and preserves the three-second selection countdown, for a 5.2-second cold boot. Boot screens repaint when their stage, selection, countdown or visible log lines change.

The password is never displayed or stored as plaintext in the source. Verification uses a local SHA-256 digest via Web Crypto (HTTPS or localhost); this is a desktop simulation, not an access-control boundary. Enter submits the native masked password field. No password or session is saved in browser storage. Volume, network and power-mode preferences survive simulated restarts within the page. `src/system.js` owns timed power/session transitions through `send(event, value)`, `update(time, reducedMotion)`, the read-only `state`, and `dispose()`. During `phase: 'booting'`, `state.boot` exposes the stage, selected entry, countdown seconds (`null` when inactive) and immutable visible log lines; otherwise it is `null`. `boot-select` accepts `normal` or `fallback`, `boot-confirm` starts the selection and `boot-interrupt` cancels autoboot. These events apply only to the Limine menu with the lid open. Labels, paths, durations and timed logs live in `src/boot-profile.js`, based on the [Limine 12.9.3 configuration and source](https://github.com/Limine-Bootloader/Limine/tree/v12.9.3) and [CachyOS boot documentation](https://wiki.cachyos.org/configuration/boot_manager_configuration/). Model brightness combines system state with lid brightness.

The slim laptop has a perforated cooling grille, side vents, two USB-A sockets, USB-C, an Ethernet socket with a folding lower jaw, and a barrel power socket. All ports start empty. Click or tap the camera cover above the display to slide it open or closed. Keyboard users can tab to the Camera privacy cover button; it becomes visible when focused. The camera indicator stays off, and the scene does not request camera access.

`createLaptop()` exposes `ports` records with `id`, `type`, `group`, and `anchor`. Attach future connector models to the appropriate anchor, whose local +Z points out of the socket. The Ethernet group's `ethernet-jaw` pivots around local X; rotating it to 0.5 radians opens the mouth. `webcam.setClosed(boolean)` and `webcam.update(deltaSeconds, reducedMotion)` control the cover.

Click or tap the front-center lifting notch to close or open the laptop lid, or tab to the Laptop lid button. Closing the lid leaves screen focus; screen and camera-cover controls become available again once the lid is fully open. `lid.setClosed(boolean)` and `lid.update(deltaSeconds, reducedMotion)` control the hinge, with `closed` reporting the target state and `moving` reporting an unfinished transition. Reduced motion changes the lid state immediately.

At a lid opening of 20 degrees or less, the display and its glow fade out over 100 ms. At 30 degrees or more, the display waits 150 ms, then fades in over 600 ms, continuing after the hinge settles. Reduced motion bypasses these delays and fades. `lid.update()` continues updating the display while returning whether the hinge geometry changed.

Run `npm run check` to verify imports, geometry budgets, chassis/port clearance, attachment orientation, camera cover behavior, desktop controls, power/session transitions and scene interactions. Credential tests use a crypto-boundary fixture rather than the real password. These checks do not measure GPU pixels, native browser behavior, screen-reader output or FPS.

`src/screen.js` owns desktop state, layout and input; `src/screen-painter.js` paints that layout without owning state or textures. `src/power-input.js` handles physical and accessible power-button gestures, while `src/system.js` owns power/session transitions. Interaction checks share `scripts/test-interactions.mjs` and run view, keyboard, hardware and desktop scenarios sequentially through `scripts/check-interactions.mjs`.
